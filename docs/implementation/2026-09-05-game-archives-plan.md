# 游戏档案与酒店前台实施计划

范围：落实反馈中的阶段 1–2，不改变赔付表、RNG、升级候选权重、食物、加班目标或下注规则。保留现有未提交的平衡测试改动。

## 交付顺序

1. 档案数据层：在规则 RunState 之外保存起始快照、规则指纹、逐操作日志、当前快照与跨局目录。记录成功/拒绝命令、系统动作、事件、候选、资源及轮盘变化；不截断为 100 转。旧存档作为有明确起点的检查点导入，不推测过去事件。
2. 续玩与备份：保留旧 v2/v1 存储键，自动存档、具名手动备份、历史局、导入导出。新局保留旧局，恢复备份创建分支。存储错误和多标签冲突明确提示，保留内存数据供导出；不静默覆盖坏档。
3. 种子与复盘：输入/随机/复制/收藏种子，同种子重开。复盘包携带规则指纹；同版本可执行只读确定性核验，不播放或修改实际游戏。版本不同只读查看，不自动套用新规则。
4. 前台 UI：主菜单、继续游戏、新游戏、历史记录、日志查看器、设置和收藏图鉴。游戏中随时打开日志/备份/导出/返回前台；查看期间暂停演出。图鉴复用现有准确文案，记录获得过的升级，提供路线说明与收藏；没有局外数值加成。
5. 有限验证：新档案/迁移/拒绝操作/容量与冲突/导入校验/复盘一致性单测，菜单与日志关键交互测试，类型检查与构建；最后仅做隔离浏览器冒烟，不操作用户 Chrome 实际对局，不跑大批蒙特卡洛。

## 本轮技术取舍

- 不引入后端、账号、云同步或新依赖。本地版本化档案采用原子 JSON 存储，完整日志随档案导出；容量不足明确停止自动推进并要求备份，不丢弃旧局来腾空间。
- 规则状态与档案分离，保留严格 v2 解码及现有结算小票。UI 不重算奖励，日志从真实命令结果捕获。
- 构建时根据 core 和 content 源码生成规则指纹，覆盖本地未提交赔付调整；旧局的历史规则未知须明确标记。
- 收藏包含升级图鉴、喜欢的历史局和种子。图鉴不控制升级掉落、不解锁额外强度。
- 操作日志记录游戏指令与系统状态推进，不记录鼠标移动、每帧动画或无关浏览行为。
- 单档案导入有大小、结构、命令和事件校验；导入不覆盖当前局，需显式恢复。跨浏览器转移通过导出/导入完成。

## 完成标准

- 开新局后旧局仍能查看、导出、另存恢复；刷新能回到保存阶段，结算不重复入账。
- 每次命令尝试都能查看结果、资源变化和原始调试数据；候选与永久轮盘变化可检查。
- 旧档案保留原始检查点，日志明确“从此处开始”，不声称完整历史。
- 不同规则指纹禁止续玩和一致性核验，但允许只读查看/导出。
- 所有写入失败、导入失败可见，不清空或替换已有数据。
