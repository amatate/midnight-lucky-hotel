# 构筑分化试玩版 · 2026-09-22

范围：三条路线各增加一个有不同取舍的部件；调整点餐时机、小费刷新和整备提示。沿用六间客房、现有手机 UI 和基础赔付表；本轮不扩关、不做 Jackpot，不发布线上版本。

## 新玩法

下表的 B 指触发时的当前下注，不是余额。

| 路线 / 部件 | L1 | L2 | 取舍 |
| --- | --- | --- | --- |
| 水果 · 陈酿果桶 | 每个有樱桃线、柠檬线或水果沙拉奖励的付费转储存 1 格；第 3 格立即开桶，额外获得 12B | 开桶提高为 24B | 占槽、延迟兑现；免费转不储存也不开桶，不能救活完全打不出水果的机器 |
| 小教堂 · 还愿烛台 | 转前花 1 小费，存入最多 3 点预兆；之后首次未被裂缝禁用的结算，每点支付 2B | 每点支付 4B | 与保留预兆、攒小费精炼形成竞争；裂缝可能延后兑现 |
| 故障 · 减震飞轮 | 裂缝造成的部件失效数量减少 1；最多 1 个可见实体裂缝各支付 2B | 减少 2 个失效；最多 2 个实体裂缝各支付 3B | 不清除裂缝，过量裂缝仍会禁用部件；保护部件也可能减少保修欺诈的机会 |

- 果桶每个付费转最多储存一格，多条线不会重复计数。储量跨班、跨房、跨重试保留；可在接近开桶时点餐，放大实际奖金。
- 点烛不占干预点或祈祷次数，不立即给钱；空转或免费转也能兑现。存入的预兆已经从预兆池扣除，不会再被收集器重复兑现。
- 飞轮自身免疫裂缝禁用，先提供保护再分配其余失效。重复显示同一个实体裂缝只计算一次裂缝奖金。
- 果桶、烛台升级保留储量，替换该部件会丢弃对应储量。候选、详情浮窗与替换提示均说明代价。

## 食物、小费与整备

- 厨房每班仍只能点餐一次，但改为任意一次转动前可买，不必第一转就买。原价与三转持续时间不变；免费转也消耗持续时间。界面提示剩余付费转和购买后下一注资金风险。
- 花小费刷新时保证至少出现一个不同的升级 ID，不会只把原来的三个换位置。没有合法新组合时不扣小费、不消耗随机数。
- 整备候选按扣除整备费后的余额判断可购性，避免出现购买后付不起附加费用的选项。界面说明购买后余额与下一间房下注储备；未改整备价格。

这些不是玩家整局通关率：新版多装备一个部件，后半段水果样本也改变了点餐时机；未模拟获取成本、升级路线、整备和重试，也未寻找最优策略。纯七样本前后都是全过，不能据此判断其实际成型难度。故障的 “mature” 脚本标记仅代表预设部件为 L2，不代表最优成型构筑。

当前结论：果桶提供了缺失的水果爆发节点；飞轮改善故障前中期稳定性，但故障后期仍是明确的待观察问题。本轮不宣称三线已完全平衡，也不以小样本全面上调或下调倍率。

## 建议试玩顺序

1. **水果**：保持已有水果核心，选果桶。观察 2/3 的准备提示，在下一次预期命中前点餐，检查第三次付费水果命中的开桶奖金和结算日志；不要把多条线或免费转当作多次充能。
2. **小教堂**：积攒预兆、拿到烛台后，比较“花 1 小费立即锁定下一转奖金”和“继续攒预兆、保留 3 小费精炼”。点烛后即使未连线也应支付；若烛台因裂缝失效，应保留储量而非吞掉。
3. **故障**：比较有无飞轮时核心部件的失效数量。尝试保留少量裂缝，不要继续堆裂缝而忽略保护上限；同时观察保修欺诈的触发是否减少。

优先收集：果桶是否让你主动规划点餐；烛台是否值得花小费；飞轮是否改变装配选择；后两间房是否仍只能靠重试碰运气。每条路线留一份日志即可，不必穷举。
