# 3D coin tray — 2026-10-14

Status: playable coin tray integrated into all four classic cabinets. The user approved the physical effect and requested a GitHub release on 2026-10-14; existing audio is retained. The earlier prototype checks below remain scoped to their original session. Real-phone performance acceptance is still pending. Deployment status is recorded by the repository's Pages workflow.

## Request and scope

The design review recommended a local 3D receiving pan first, not a full-cabinet 3D rewrite. Current dependencies and sources were rechecked during implementation.

- Reuse installed Three.js 0.186.1; add pinned production dependency `@dimforge/rapier3d-compat` 0.21.0.
- Standalone no-wager demo: `?mode=classic&demo=coins&lang=zh` (or `en`). It branches before mounting `MachineScreen`, so no machine save is opened. A malformed existing save does not prevent the demo.
- Existing classic cabinets share a receiving pan below the bet/spin controls. Positive-net settlements trigger small/medium/large bursts. Losses and break-even do not celebrate. No change to original engines, strips, probability, wheel endpoints, storage adapters, hotel rules, or motor/reel motion.
- Scope is deliberately a fixed-camera effect with a procedural coin and pan. No new generated bitmap, licensed samples, full-machine model, paid service, purchase or cashout.

## Design

Keep enamel `#14291f`, dark `#09130d`, pale brass `#b5a077`, ivory `#f2e3c0` and coin gold `#caa353`. Retain Smiley Sans display, Barlow Condensed utilities, existing readable body text. New signature: coins physically leave a rear mouth and land in a shallow receiving pan. Do not shower the reels or cover controls.

The game-feel skill guided bounded feedback tiers and collision-timed audio; frontend-design guided the understated brass/green bowl, retained typography, dark ledger-label backing and mobile controls. First visual inspection found over-bright metal; exposure and light intensity were reduced, rails beveled and the floor ribbing changed from many meshes to a texture. A 320px fallback aspect-ratio overflow was corrected and rechecked at document width 320px.

## Implementation and boundaries

- `coin-plan.ts`: cosmetic-only seeds and 8/18/32-coin presets. Never imports or advances game RNG. Counts express presentation intensity, not cash or payout units.
- `coin-physics.ts`: Rapier cylinder bodies with CCD, fixed 1/60 step, at most four catch-up steps, five static pan colliders, friction/restitution, sleep-capable bodies. Starting another burst clears the old bodies; 4.2–5.6s lifetimes include fade/recycling. Idle simulation takes no further steps.
- `coin-scene.ts`: shared geometry/materials through an instanced mesh, face textures, metal lighting and shadows; DPR capped at 1.5. RAF runs only during an effect; resizing renders once. Background/pagehide clears visual objects. Unmount/quality changes dispose physics, geometry, textures, instance buffers, shadows and renderer. This uses a second small WebGL canvas, not a rewrite of the reel renderer.
- `PayoutTray.tsx`: on-demand dynamic import after the first profitable payout; demo warms the scene intentionally. Loading failure after 8s or context loss falls back to lightweight CSS animation. Reduced motion skips physics/render initialization and shows a static tray. Switching quality does not replay an already consumed cue. Effects never call settlement or mutate credits.
- `CoinDemo.tsx`: isolated three-button comparison. Repeat clicks replace, not accumulate. Demo switches are session-local; shared audio settings intentionally remain shared.
- `presentation/coin-impact.ts` and `audio.ts`: three original short synthesized metal contacts. Contact intensity controls level; lateral position controls stereo pan. Global 60ms contact throttle, six-voice contact ceiling under existing eight-voice SFX limit. Existing SFX volume/mute and visibility lifecycle apply. The old timed count-up coin sound is suppressed when 3D is selected to avoid layering fake contacts over physical ones.
- `ClassicScreen.tsx`: cue only after successful settlement. Returning/reloading restores amounts without replaying coins; a new spin clears the prior effect. 3D preference stored separately as `midnight-lucky-hotel.classic.coins-3d`; existing save shapes/keys remain unchanged.

## Loading and offline cost

The compatibility physics bundle embeds WASM. Production coin chunk is approximately **4.34 MB raw / 1.67 MB gzip** (build estimate, not measured mobile transfer). It exceeded the original 3 MiB precache cap. Instead of raising that cap or charging every player an initial download:

- Exclude only `coin-scene-*.js` from automatic precache.
- Load it only for 3D effects; same-origin bounded CacheFirst runtime cache retains at most two versions for 30 days.
- A player who has not cached physics and opens offline gets simplified visuals; settlement remains unaffected.
- Initial precache is about 2.6 MiB across 26 files. Three.js/main bundle warnings remain. A smaller external-WASM build or leaner physics library is a possible later optimization if real-device loading is unsatisfactory.

No complete offline install/update lifecycle was browser-tested in this task; the generated worker and successful subpath build were checked. Do not equate cache configuration with real-device offline acceptance.
