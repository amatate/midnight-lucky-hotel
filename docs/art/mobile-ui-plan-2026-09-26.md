# 手机固定机台 · 试玩评估与前端方案
日期：2026-09-26。状态：方案已确认，固定机台第一版已落地；见[实施记录](../implementation/2026-09-26-fixed-mobile-console.md)。以下试玩证据与样张描述保留为改动前的设计依据。

## 结论

推荐 A「固定机台 + 状态切换操作台」。保留现有素材和 React，改变的是布局模型与交互方式：从纵向网页信息流变成固定游戏舞台。HTML 本身不是问题，也无需为解决这次 UI 问题重写游戏引擎。

改动前，有意义的体验是选列干预、保留盘面、部件触发和奖金累加；阅读说明、页面上下滚动、主按钮搬家在打断它们。先修布局和可读性，再评估是否需要新机制。本次一班样本不支持难度、胜率、成瘾性或整体平衡结论。

## 三种方向

| 方向 | 怎么做 | 取舍 |
| --- | --- | --- |
| **A 固定机台，推荐** | 盘面、五槽、拉杆不动；下方同一块操作台切换准备/干预/结算。菜单和说明用抽屉 | 最大限度保留现有构筑辨识，工作范围可控 |
| B 大盘面街机 | 九宫格与拉杆占主体，部件收成一排小图标；服务/配置抽屉打开 | 一眼就知道怎么玩，但部件质感和混搭可见性减弱 |
| C 分镜式机台 | 准备看下半机台、转动聚焦九格、中奖镜头看部件 | 表现空间大，但频繁镜头切换、减少动态适配和输入时机更复杂 |

本轮不建议换引擎，也不新增数值机制。先用 A 建立稳定可玩的手机基础。

## A 的固定尺寸与适配边界

- **390×760 CSS px 作为设计画布**，不是物理屏幕分辨率，也不是承诺所有手机共享这一个真实视口。样张不计浏览器顶栏/系统刘海。
- 优先验收360–430px宽、640px以上的实际安全可用高度；390×760为标准档，360×640为紧凑档。超长屏把余量给背景/盘面，桌面居中放置窄机台。
- 窄屏不能把整张390px画布简单缩小：字与触区不能同步缩没。紧凑档缩顶冠、留白与盘面行高，保留44px以上触区、主操作56–72px及帮助正文16px。正文不靠10px字硬塞。
- 日常旋转循环不滚动主舞台。菜单、日志、部件详情、升级详情单独滚动。320px短屏/系统大字体允许独立无障碍回流，不能禁止缩放或裁掉文字。
- 游戏高度参考稳定的小视口并扣除safe-area；抽屉用实际动态可用高度。浏览器工具栏变化不在拉杆手势中缩放整台机器。参考 [MDN viewport units](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length#relative_length_units_based_on_viewport)。
- 当前样张为设计验证，不是已经完成的360px响应式实现。三张390×760样张测量一致：盘面容器top213/height288；部件架top509/height86；操作键top663/height84。每张内部无纵向溢出。

固定区域：
```text
房间 / 剩余转数                         菜单
余额              目标进度 / 干预点 / 小费
                 房间短顶冠
本转奖金（原位累加）                    账本
┌──────── 九宫格 ────────────┐  拉
│         三列、固定窗口       │  杆
└─ 第1列键 ─ 第2列键 ─ 第3列键 ┘
[真实部件1][部件2][部件3][部件4][部件5]
准备配件 / 模式选择 / 当前触发说明（复用）
次要键          固定拇指主键 + 明确费用
```

房间只改外壳材质/顶冠/背景/目标表。服务和构筑不改核心坐标。五槽混搭常驻、空槽不被虚构部件填充。

## 按钮系统：物理隐喻 + 稳定规则

不是把所有矩形按钮改成圆形。明确四种控件：
1. **主机械压键**：淡金键帽、墨绿字、金属底座；压下2px、边缘光收缩、释放短回弹。一个稳定位置承接本阶段主动作，费用永远在第二行。
2. **三列实体键**：和三列对齐，44px高。点列/键只是选中；选中压低、边框亮起、对应轮微微提亮，不立刻扣资源。
3. **准备配件键**：点餐罩、烛台、祈祷符号进入简短选项；餐食直接在三列上选目标，祈祷用四枚符号片。替代浏览器原生下拉框，明确确认后才付费。
4. **只读查看入口**：点部件看说明；菜单、账本、状态数字不使用与花钱键相同的视觉权重。查看不触发付费。

| 阶段 | 固定操作台 | 固定主键 | 费用/风险 |
| --- | --- | --- | --- |
| 准备 | 当前可用配件；多个配件超过容量时用“准备 · N项”抽屉 | 拉动一转 | ¥当前下注；免费转写“免费” |
| 转动 | 收起说明但保留区域高度 | 转动中，禁用 | 不再接受重复下注 |
| 停轮、未选列 | 只有一个干预模式时省略模式切换；多模式用嵌入式拨档 | 收下这把 | 不消耗干预点 |
| 已选重转 | 已选列高亮 + 一句风险；取消键 | 重转第N轮 | 1干预点 · 不再扣钱 |
| 已选锁轮 | 锁住列加锁标，另外两列标“重转” | 锁住第N轮 | 1干预点；每班限制照旧 |
| 已选踹击 | 保留真实确定性预览、明确永久裂纹 | 踹击第N轮 | +1永久裂纹 |
| 结算 | 当前触发源短句，部件原位点亮 | 加速结算；另保留直接结算入口 | 不再加一次“下一步” |
| 班后升级 | 独立维修台覆盖层：同时可比较三张短票，选中展开，底部固定确认 | 装入 / 改造 | 消耗和被替换部件明确列出 |

抽屉打开时暂停自动停轮/演出，保留目前帮助焦点管理。阶段变化时必须等待新的pointerdown并有短防连击窗口，不能把上一阶段的松手事件变成下一次下注；也不能为防误触再强加一层常规确认。

## 游戏手感，不增加操作负担

- 选列：约80–120ms边缘响应，短机械轻响；不震屏。
- 执行重转：只选定列转动，另外两列保持静止；费用图标在确认后消失1格。
- 普通中奖：中奖线 → 奖金表抬数 → 对应部件灯；少量金币即可，不遮九格。
- 连锁：按现有事件顺序从触发部件到奖金表；短因果句代替“事件7/8”作为主信息。完整事件队列仍在账本。
- 大奖：才用短机身震动/更丰富金币；所有动效瞬时结束、尊重减少动态/闪烁设置，不改变规则时钟或RNG。
- 结算自动回准备，正常一转仍是拉动→观察→收下；干预增加一次选择与一次确认，不做无意义“继续”。

这些是调参起点，不是声称真机触感已验收。已有拉杆声、结算声和震动事件钩子继续利用；不能因为用了图像资源就宣称游戏性或音效已变好。

## 配色、文字与样式约束

- 深底 #0c1715；正文象牙 #f2e3c0；次级文字 #c7bda4；浅金键帽 #d8c48f；警示暗红 #a63243；保护/选中青绿 #427d70。
- 深底始终配浅字，浅金/票据底始终配深字；风险红色搭配文字/图形，不只靠颜色传达。
- 得意黑覆盖房间名、机台短铭牌、列键、部件名、服务键与主要动作；Barlow用于余额/下注等仪表数字及英文顶冠。正文、风险补充与长说明保留系统中文无衬线。主键约24–26px、常用标签14–17px、部件名13px、辅助读数12–13px、长说明16px。
- 普通文字目标至少4.5:1，大字至少3:1；状态禁用虽有规范豁免，游戏仍保留可读的禁用原因。参考 [WCAG contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- 触区采用本项目44–48px目标，主键56–72px；这高于WCAG2.2 AA的24px最低门槛，不把44px误写成AA要求。参考 [WCAG target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
- 配色端点计算示例：象牙字/深底约14.38:1，次级字/深底9.79:1，深字/浅金键帽10.63:1。渐变、半透明、禁用态仍须实际渲染检查，不能只测tokens。
- 收敛现有styles.css / art-deco.css / cabinet-builds.css跨文件覆写；按surface和button variant定义成对前景/背景。房间theme只换装饰变量，不拥有正文文字色。控制文字颜色的CSS必须与背景在同一组件范围定义。

## 实施顺序与有限验收

**第一批 P0：** 修帮助正文与所有状态文字；建立固定GameViewport和紧凑档，移出页脚工具，保留真实九格与拉杆。验收390×760及360×640不滚动完成正常一转；大字体可访问。

**第二批 P1：** 统一PhysicalButton、ReelKey、ActionDeck；准备选目标改为点盘面；升级改独立维修台。确认选择/取消零消耗，确认恰好扣一次，触摸不会误下注。

**第三批 P2：** 奖金表原位累加、触发部件到数字的局部反馈、精简主舞台文案；不改任何概率、数值、候选池或进度规则。

只做三个尺寸、四个关键阶段、一次真实班次的定向浏览器检查，加上受影响控件单测；不跑无关数值模拟。手机浏览器仿真通过后，还需一次实际手机手指体验，特别是安全区、浏览器工具栏、轻触/拖动和音频解锁。

保持：确定性结算、逐事件公开奖金、混搭五槽、旧存档与日志、固定九格窗口、单次手势一次消费、免费转与房间目标语义。任何新增overlay都不能篡改已结算结果或泄漏未播放的金额。

### 字体修订 · 2026-09-26

用户反馈机台部分字体过于普通，因此把得意黑从主标题延伸到实体控件与短铭牌，减少系统字体造成的网页感；英文顶冠使用带字距的Barlow。显式声明字体真实字重/倾斜信息，禁用合成字形，不用阴影描边堆出假粗体。费用与数字保留独立仪表字体，长风险文字不全部艺术字化。未下载新字体，未增加资源体积。

仅修改方案HTML与本说明，尚未应用到运行中的游戏。重新渲染390px母版与360px页面；三状态机台仍高760px、部件架与主键坐标一致，部件名称未越出插槽，页面无横向溢出。此验证不等于360×640紧凑档已实现。
