# 构筑组件 × 六房机型 · 已批准方案

目标：让“我装了什么部件”和“我到了哪间房”能直接从机器上看出来。延续淡金、墨绿、原有水果图案与得意黑字体；以手机单手游玩为先。本轮只新增方案和概念图，不改游戏代码、规则、存档，不发布。

## 1. 核心结构：房间换外壳，构筑装组件

房间外壳与部件装配是两条独立的视觉轴，不建立十八套彼此独立的整图界面。

```text
客房环境 / 顶冠 / 侧轨 / 目标仪表       ← 当前房间
余额、阶段、目标、干预点、小费、账本     ← 当前状态
固定九宫格 + 右侧拉杆                  ← 原有玩法与输入
五槽实体组件架                        ← 五个真实已装部件
当前可用准备 / 干预操作                 ← 服务、部件和当前阶段
一个主操作键                          ← 原有控制器
```

五槽可混搭。厨房服务不等于水果构筑；不能仅凭服务或“主路线”整体替换组件、隐藏其他路线部件。部件缺席就不显示它的实体或读数。开局无部件仍为统一的五槽基座。

## 2. 构筑下半部

| 家族 | 实体组件语言 | 直接可见的功能状态 | 操作边界 |
| --- | --- | --- | --- |
| 水果 | 玻璃果酱罐、樱桃压榨机、柠檬注入器、铜箍果桶 | 果桶三格储量；触发时对应组件点亮并送出奖金标签 | 果桶自动结算，不新增“开桶”按钮；点餐仍属于厨房服务 |
| 小教堂 | 预兆收集仪、三联祝福棱镜、小钟、献祭币座、还愿烛台 | 预兆池与烛台已存预兆分开；烛台可见储量，点烛后等待兑现 | 点烛仍执行现有命令、消耗和可用条件；不能点一下组件就无提示花钱 |
| 故障 | 飞轮、弹簧、电容、磁铁、保险丝、保修盒 | 飞轮保护上限、电容储量；失效部件暗下并显示裂纹标识 | 不画不存在的“压力/温度”数值；脚踹仍只在允许的停轮阶段出现 |

其他部件先沿用现有图标作为占位，再补齐 19 个部件的实体小件。不因缺少新美术而让某个已装部件消失。

统一状态：空槽 / 已装 / 已有储量 / 当前触发 / 本转失效。升级增加一个明确的 L2 铭牌和适当结构细节，不靠体积变大或持续闪光表示强度。点击组件继续打开只读说明，费用动作保留明确按钮。

免费转继续按原规则计入目标，不消耗付费转刻度。没有正在挑战的房间时，保留当前基础机壳；重试不重置构筑美术。顶冠、侧板与目标仪表可以不同，九格坐标、拉杆位置、五槽顺序和主动作位置保持一致。

## 4. 视觉与手机约束

- 基础色：墨绿 `#0c1715`、浅香槟金 `#d8c48f`、象牙白 `#f2e3c0`、哑铜 `#9d8558`、暗红 `#a63243`、炭黑 `#222728`。房间只引入少量材质本色，不做高饱和全屏换色。
- 标题保留 Smiley Sans / 得意黑；正文保持现有中文无衬线；数字延续 Barlow Condensed。概念图中的生成文字不直接作为游戏文字资源。
- 记忆点集中在“部件真实装在槽里”。材质使用浅浮雕、局部磨损、少量玻璃反光，减少重复金框；不要每个控件都做浮夸立体装饰。
- 常见手机目标宽度 390px，兼容 320px；五槽不横向滚动，名称可缩略，详情点击展开。触控命中区域至少 44px。
- 九格不能被组件、背景或演出挤没。准备区使用紧凑横条，停轮后就地切换干预区，避免同时堆满所有操作。
- 普通手机优先让机台与主要动作在一屏附近完成；短屏、字体放大时允许纵向滚动，不通过裁剪内容硬塞进一屏。主动作停靠不得遮住盘面或说明。
- 桌面沿用窄机台作为主角，环境在两侧展开；说明与日志可以侧栏展开，不把九格横向拉宽。

## 6. 确认后的实施顺序

1. **先做一个完整样板**：基础五槽装配台 + 景观房外壳 + 果桶 / 烛台 / 飞轮代表组件，验证混搭、触发和失效。先把手机大小下的字体、按钮、组件密度定准。
2. **补齐构筑组件**：所有部件都有可辨认外形，准备操作整合进机台下半部，保留说明浮窗；服务区独立于部件家族，不制造路线锁定。
3. **铺开六房**：共用机台结构，新增六套房间材质配置、顶冠 / 侧轨美术与三种目标仪表。若第一阶段比例未通过，不批量生成全部素材。
4. **必要验收**：320px / 常见手机 / 桌面各做定向检查；只抽查一次拉杆、一次组件触发、一次房间切换和混搭失效，不跑与视觉改动无关的大规模数值模拟。

工程建议：仅在应用 / 呈现层增加 `RoomCabinetSkin`、`InstalledPartVisual`、`PreparationDeck` 等展示模块；从既有状态和已播放事件得到读数，图像负责静态材质，React / CSS / SVG 负责数字、按钮、灯、充能和交互。图片懒加载与离线缓存按房间资源安排，加载失败仍能操作。

不能破坏：确定性随机数与结算、旧存档、日志与种子、逐步公开奖金、九格固定窗口、一个手势只转一次、弱动画与帮助暂停。房间换皮不消耗资源、不改变概率、不触发新随机数。
