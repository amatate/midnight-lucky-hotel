# 午夜好运酒店：“一拉一爆”体验重做设计

- 日期：2026-08-30
- 状态：待用户书面复核
- 产品范围：现有 React Web/PWA 功能原型的表现层与信息层重做
- 核心路线：方案 A——先完成共用的拉动、停轮、中奖与选项解释，再以厨房／水果路线做第一条完整精修路线

## 1. 目标与边界

本轮不增加构筑数量，也不重写已验证的规则核心。目标是让玩家在前三次拉动内感到老虎机有重量、有期待、有奖励，并在第一班结束时看懂三个升级、选出一个明确协同，在下一班直接看见该升级改变了机器。

必须达到的体验：

1. 拉杆会跟手、蓄力、越过卡点并回弹，触发瞬间同时有运动、声音和可选震动。
2. 三根转轮真实滚动并依次停下，最终显示严格等于规则核心已生成的结果。
3. 中奖线、金额、部件触发和余额变化构成一条可见因果链，而不是一组内部事件名。
4. 普通中奖、构筑连锁和机器失控具有三档明确但克制的反馈强度。
5. 所有服务、升级和部件始终用玩家语言说明“做什么、何时触发、当前会改变什么”。
6. 从负期望机器到超过 100% RTP 的转变可被看见，但精确概率与 RTP 仍遵守信息工具解锁规则。

本轮明确不做：

- 新路线、新升级、新货币、局外成长或商业化；
- 改变基础概率、赔付、合同或候选生成；
- 用动画制造秘密保底、假中奖或假“差一点”；
- 为了表现修改 RNG、盘面、余额或结算顺序；
- 引入重型游戏引擎或把 React 原型迁移到 Unity。

## 2. 设计主张

### 2.1 具体主题

这不是一个赌场主题的手机 App，而是一台放在 1980 年代破旧午夜酒店前台、被玩家不断拆改的实体老虎机。玩家面对的是一件机器，而不是一组仪表盘卡片。

- 玩家：喜欢轻量构筑、概率改造和连续爆发的手机玩家。
- 页面唯一任务：让玩家愿意再拉一次，并能解释这次结果为何发生。
- 视觉风险：在 320–430px 宽度内保留机身右侧的实体拉杆。它会牺牲少量盘面宽度，但成为游戏最容易被记住的动作与轮廓。

### 2.2 视觉关键词

`黄铜机械`、`搪瓷符号牌`、`烟熏玻璃`、`旧酒店票据`、`暗红绒布`、`不稳定的暖色灯泡`。

禁止沿用的默认风格：

- 大面积紫色半透明卡片；
- 通用 SaaS 渐变、胶囊标签和均匀圆角；
- 用 emoji 直接承担最终符号美术；
- 装饰性但没有规则含义的编号、数据块和发光边框。

## 3. 视觉系统

### 3.1 色彩令牌

| 令牌 | 色值 | 用途 |
|---|---|---|
| `night-ink` | `#0B0908` | 页面背景、机身深处 |
| `aged-brass` | `#B8893E` | 机框、拉杆、分隔结构 |
| `warm-enamel` | `#F2E3C0` | 符号牌、正文高对比面 |
| `hotel-red` | `#A92F36` | 主操作、中奖线、危险成本 |
| `payout-gold` | `#FFD45A` | 金额、金币、正向爆发 |
| `verdigris` | `#347568` | 正期望、维修与稳定状态 |

信息窗和操作托盘使用 `night-ink` 的浅一级派生色，不再增加第七个主色。金色只用于真实价值与关键动作；红色只用于拉动、中奖线和明确风险，避免所有元素同时争夺注意力。

### 3.2 字体角色

- 展示字：`Smiley Sans`（得意黑）或随包内置的同许可证 WOFF2，用于游戏名、大中奖和班次标题；斜切轮廓呼应旧霓虹招牌。
- 数字字：`Barlow Condensed`，启用 tabular numbers，用于余额、赌注、倍率和滚动金额。
- 正文字：`PingFang SC`／`Microsoft YaHei`／系统无衬线，用于规则说明和按钮，不依赖在线字体服务。

字体资产必须本地打包并保留许可证；离线 PWA 不访问远程字体。

### 3.3 材质与形状

- 机身使用方正切角和细黄铜压边，主要半径 4–10px；只有拉杆球头和指示灯使用完整圆形。
- 符号牌为暖白搪瓷，带轻微内阴影和边缘磨损；同一符号保持固定图形和色彩。
- 信息说明使用酒店行李签／维修票据语汇，但纸张形状只服务于候选与规则说明。
- 粒子、噪点和磨损属于静态材质，不覆盖可读文字和中奖线。

布局原则：

- 机身和拉杆是页面英雄，占据首屏主要面积；余额与 ¥200 退房目标使用旧酒店房号翻牌器造型，成为除拉杆外最明确的世界观细节；
- 顶部只显示余额、目标、班次、下注和三个稀缺资源；
- 服务、下注、干预和结算共享一个上下文托盘，不再同时铺开多个面板；
- 部件栏保持一排，但每个槽有图形、触发灯和可点开的完整说明；
- 升级选择是独立全宽场景，避免三张窄卡挤在老虎机下方。

## 5. 一次拉动的节奏

### 5.1 输入与拉杆

拉杆使用一个连续的 0–1 进度，不再只判断指针是否跨过 48px。

1. 指针按下后球头即时跟手，前 60% 行程轻、后 40% 增加视觉阻力。
2. 进入 72% 行程时出现一次机械卡点：轻微刻度声和可选 8–12ms 震动。
3. 松手达到 82% 即触发；不足 82% 则回到原位且不扣款。
4. 触发后拉杆用约 70ms 撞到底，再以约 210ms 的 back-ease 回弹。
5. 无障碍“拉动”按钮保留，播放相同但缩短的压下／回弹反馈。

拉杆表现不能锁住输入超过 300ms，也不能在动画开始前延迟发送 `SPIN`。扣款与结果仍由现有指令即时、原子地决定。

### 5.2 转轮运动

`SPIN` 后核心已经生成最终 `ReelDraw`，表现层隐藏最终盘面并播放纯视觉滚动：

- 0–140ms：加速，符号纵向拉伸并产生运动模糊；
- 140–820ms：稳定转动，三个轮轴速度略有差异；
- 820–1000ms：第一轮减速、越过半格再回正；
- 1040–1220ms：第二轮停下；
- 1260–1440ms：第三轮停下；
- 1440ms：自动发送一次 `REELS_STOPPED`，进入真实干预窗口。

普通重转只重播目标轮约 620ms；维修锁轮突出被锁轮，另外两轮依次停；踢机器显示确定性位移和裂纹落入转轮，而不是伪装成随机重转。

滚动过程中出现的过渡符号只用于表现，最终三格、停点和物理身份必须来自核心 `ReelDraw`。不得根据输赢延长第三轮、重排符号或制造假近失。

### 5.3 干预与自动推进

- 停轮后若存在可用干预，托盘只显示一个主按钮“收下这把”和当前合法的重转／服务动作。
- 无合法干预时，盘面停留 300ms 后自动接受结果。
- 玩家选择干预后重新播放对应轮运动；每转仍最多一次干预。
- 接受结果后自动播放结算，演出结束自动发送一次 `PRESENTATION_COMPLETE`。
- “加速”和“直接结算”保留；直接结算跳过表现但不跳过任何规则事件。

这将普通一转从“拉动→停轮→接受→完成结算”缩短为“拉动→必要时做一次决策”。

## 6. 中奖与连锁反馈

### 6.1 纯表现摘要

新增纯表现函数，从 `GameEvent[]` 和当前赌注导出：

- 总奖金；
- 基础中奖线列表与对应格子；
- 部件触发顺序；
- 效果链长度；
- 奖励强度 `none | win | chain | runaway`。

它不写入 `RunState`，不产生 RNG，也不修改事件顺序。建议分档：

| 档位 | 规则 |
|---|---|
| `win` | 总奖金大于 0，且少于 2 条中奖线、少于 2 次部件触发、总额低于 3 倍赌注 |
| `chain` | 至少 2 条线、至少 2 次部件触发、获得免费转动，或总额达到 3–8 倍赌注 |
| `runaway` | 出现 `OVERLOAD`、效果事件达到 6 个，或总额达到至少 8 倍赌注 |

阈值只控制反馈强度，不影响支付金额。

### 6.2 三档反馈包

#### 普通中奖 `win`

- 对应中奖线从左到右点亮 420ms；
- 三个符号做一次 1.08 倍 squash/pop；
- 6–10 枚金币从中奖线飞向余额窗；
- 精确金额以 `+¥X` 上浮，余额滚动到新值；
- 一次短促三音符和 12ms 震动。

#### 构筑连锁 `chain`

- 中奖线依次点亮，触发部件槽亮起并向盘面发出一道连线；
- 每个事件推动左侧“连锁计数器”，数字使用 back-ease 落定；
- 18–28 枚复用金币、轻微 2–3px 机框震动；
- 金额分段累加，让玩家看到“基础奖→部件奖→躁动／服务奖”；
- 音高随链条上升，震动使用短—短—中节奏。

#### 机器失控 `runaway`

- 先有 60–90ms 视觉蓄力，再触发机框灯泡、支付窗和中奖线同步爆发；
- 36–56 枚有上限、可复用的金币，金额在约 650ms 内滚动；
- 机框最大位移不超过 6px，快速衰减并回到静止；
- 显示本转精确因果摘要，例如“3 条线 · 4 次部件触发 · 躁动 ×2”；
- 使用和弦、低频撞击和可选强震动，禁止阻塞下一次输入超过 150ms。

未中奖不播放嘲讽动画。躁动增加时只让机身内部多亮一格不稳定灯，明确告诉玩家“下一次中奖 +0.5× 赌注”。

### 6.3 可访问性

- 原有“减少闪烁”改为“减弱动态与闪烁”，同时尊重操作系统设置；
- 减弱模式下取消模糊、屏幕震动、弹性缩放和粒子飞行，以 120–180ms 淡入／静态高亮替代；
- 声音、震动和动态反馈互为冗余，不得成为理解规则的唯一渠道；
- 浏览器不允许声音或震动时静默降级，规则继续运行。

## 7. 选项可理解性

### 7.1 服务选择

每个服务入口固定显示四层信息：

1. 一句话玩法身份，例如“稳定救场”或“主动制造故障”；
2. 每班可做什么及费用；
3. 它最适合的两类升级；
4. 一个真实代价，例如“食物会稀释转轮”“踢击留下永久裂纹”。

### 7.2 升级卡

三张升级卡不再显示内部英文标签。每张卡必须包含：

- 名称、类型与路线；
- 完整一级效果；
- 若已经拥有，明确显示“一级→二级”的变化；
- 基于当前状态的即时影响，例如“第 1、2 轮柠檬各 4→6”或“当前已有 2 个裂纹来源”；
- 一条诚实的协同／风险提示；
- 需要选择转轮或符号时，在同一张卡内预览应用结果，再确认获取。

候选角色翻译为玩家语言：

- 协同：`强化现有组合`；
- 转向：`修补风险／换路线`；
- 变数：`高风险改规则`。

### 7.3 部件栏

- 槽内使用独立图形和短名，不再把名称压缩成纯文字块；
- 触发时槽位灯亮、等级环脉冲，并与盘面事件同步；
- 点击后显示完整效果、二级效果、每转／每班限制和本局累计贡献；
- 因裂纹暂时禁用时显示明确裂痕遮罩和“本转失效”，结算后恢复。

### 7.4 构筑变化可视化

应用转轮改造时，目标转轮抽出一段 600–900ms 的“维修票据”演出：

```text
第 2 轮 · 柠檬木箱
柠檬 4 → 6        总长度 12 → 14
这一轮抽到柠檬的机会提高
```

未拥有计算器时只显示副本数和诚实的“提高／降低”；拥有计算器后才补充精确概率；拥有会计账本后才显示 RTP 变化。

## 8. 厨房／水果首条精修路线

共用表现完成后，第一条端到端精修路线固定为深夜厨房：

1. 买食物：硬币从余额进入厨房铃，食物牌滑入指定转轮，显示长度与副本变化。
2. 食物出现：食物牌跳出盘面，被餐铃盖收走；未来三转的 `+25%` 以三格餐券显示并逐转撕掉一格。
3. 柠檬感染：中奖线先亮，线外目标格被黄色汁液／盖章替换为柠檬，再重新检查中奖线。
4. 果酱罐：每条樱桃线给罐子增加一层刻度，下一条樱桃线明确显示额外倍率。
5. 水果沙拉：樱桃、柠檬、铃铛三个字面图案分别圈出，再合成额外奖金；百搭不应误亮。
6. 剩菜打包：消耗后的食物沿票据路径返回当前最短转轮。

其他路线保持完全可玩并获得共用拉杆、转轮、中奖和选项说明，但其专属特效在后续独立设计周期精修。

## 9. 架构边界

继续保持现有目录职责：

```text
src/core          规则、RNG、状态机、结算；本轮原则上不改行为
src/content       玩家可见升级说明与静态内容
src/presentation 事件摘要、时间线、声音、震动、金币池与反馈档位
src/app           机身、拉杆、转轮、上下文托盘、升级／部件 UI
```

关键接口：

- UI 只发送现有 `GameCommand`，自动停轮与自动完成结算也必须通过命令；
- 表现层只消费 `RunState.pendingSpin.draw` 和有序 `GameEvent[]`；
- 所有计时器在隐藏页面、恢复存档和组件卸载时可取消；
- 每个自动指令有一次性 guard，防止 React effect 重跑造成重复扣款或重复结算；
- 跳过时间线后得到的最终 `RunState` 必须与完整播放完全一致；
- 不把临时动画状态写进持久化 schema。

## 10. 测试与验收

### 10.1 自动测试

1. `presentationSummary` 对零奖、普通奖、多线、部件连锁、免费转动和过载正确分档。
2. 拉杆低于阈值不发送 `SPIN`；达到阈值只发送一次；点击备用按钮走同一入口。
3. 三轮自动停下只发送一次 `REELS_STOPPED`，展示最终格严格等于 `pendingSpin.draw.grid`。
4. 无干预自动接受；有干预时等待玩家；重转后只重播合法目标轮。
5. 完整演出与直接结算得到完全相同的最终状态。
6. 24 个升级都具备非空一级说明；14 个部件具备二级说明；动态影响不泄漏未解锁的精确概率／RTP。
7. 减弱动态、页面隐藏、恢复中间阶段和组件卸载均不产生重复命令或遗留计时器。
8. 320、390、430px 宽度没有横向溢出，所有主要触控目标至少 44px。

### 10.2 视觉验收场景

固定 390×844 截图与真实浏览器观察：

- 初始机器与服务选择；
- 拉杆 0%、卡点和到底三个姿态；
- 三轮旋转、第一轮停下、全部停下；
- 普通中奖、构筑连锁、机器失控；
- 三张升级卡及应用前后预览；
- 减弱动态模式；
- 320×568 最小屏幕。

### 10.3 真人试玩门槛

同一名玩家不阅读外部攻略，从新局开始完成第一班：

- 10 秒内知道主要动作是拉杆；
- 第一次拉动能感知“蓄力→滚动→依次停下→结果”；
- 第一次中奖能指出中奖线和到账金额；
- 第一班结束后，能用自己的话解释三个候选中的至少两个；
- 选完升级后，下一班能指出机器哪里发生了变化；
- 试玩者主观愿意“再拉三次”，否则本轮不算完成。

## 11. 自审结论

- 主题特异性：拉杆、黄铜机框、机械支付窗、酒店票据和维修演出均来自本游戏世界，不是可复用到任意 App 的装饰。
- boldness 控制：唯一高风险轮廓是右侧实体拉杆；其余布局和材质保持克制，避免全屏同时发光。
