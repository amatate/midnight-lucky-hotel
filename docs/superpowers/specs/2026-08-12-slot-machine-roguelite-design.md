# 午夜好运酒店：老虎机构筑 Roguelite 功能原型设计

- 日期：2026-08-12
- 状态：已完成对话确认，等待书面规格复核
- 目标平台：手机竖屏 Web/PWA
- 单局时长：6–10 分钟

## 1. 产品主张

这不是一款让玩家被动碰运气的老虎机游戏，而是一款让玩家组装、测量并最终击穿老虎机的轻量构筑 Roguelite。

玩家的核心幻想是：

> 我不是在碰运气，而是在把一台负期望老虎机改造成能够持续盈利并不断连锁的失控机器。

老虎机提供短周期的期待、停轮和奖励反馈；长期游戏性来自玩家对概率、波动、触发规则和资金风险的主动改造。

功能原型只以“开发者自己是否会主动再开一局”为成功目标，不围绕商业化、留存付费或广告设计。

## 2. 设计目标

### 2.1 必须实现的体验

1. 开局时，玩家明显感觉机器正在消耗本金。
2. 玩家通过构筑改变真实的图案分布、中奖规则和连锁行为。
3. 合理构筑可以在中段跨过 100% 预计回报率。
4. 跨过盈亏平衡后，情绪从“勉强求生”转为“观看自己设计的机器失控”。
5. 坏结果出现时，玩家拥有少量但关键的人工救场机会。
6. 胜负可以归因于构筑、资金和干预选择，而不只是初始随机种子。
7. 一局结束后，玩家自然产生尝试另一条构筑路线的欲望。

### 2.2 明确不做的内容

功能原型不包含以下内容：

- 完整赌场酒店场景和精细美术；
- 故事章节、角色对话和多个结局；
- 每日挑战、排行榜或社交系统；
- 正式局外解锁树；
- 广告、付费复活、付费抽取或真钱兑换；
- 云存档、账号和跨设备同步；
- 超过三条的完整首发构筑路线。

这些项目属于玩法验证后的独立决策，不影响本原型验收。

## 3. 主题与气质

游戏发生在一间午夜营业的破旧赌场酒店。整体采用荒诞黑色喜剧，而不是纯恐怖或明亮卡通。

酒店部门为老虎机玩法提供不同的构筑来源：

- 维修工负责锁轮、额外干预、拆除裂纹和降低波动；
- 午夜厨房提供食物图案、持续增益和消费返利；
- 小教堂提供祈祷、献祭、恶兆和高风险倍率；
- 保安允许踹机器、摇晃和制造可利用的故障；
- 会计室提供概率、预计回报率、波动和破产风险信息。

所有人物和服务都围绕老虎机生效，不扩展成酒店经营或第二套小游戏。

## 4. 单局结构

### 4.1 夜班流程

一局包含五个班次，每班三次基础转动，共十五次基础转动。

1. 开局从三个候选中选择一个主要酒店服务。
2. 每个班次开始时选择保守、正常或豪赌档位。
3. 连续完成三次老虎机转动；每班共享两点干预点。
4. 班次内可以尝试一个可选合同，成功获得一枚小费。
5. 前四个班次结束后，从三个候选中免费选择一个构筑升级。
6. 第五班次结束后结算退房目标；此时不提供对正常通关无用的升级。
7. 达标玩家可以退房，或者进入续住模式；选择续住后继续获得构筑机会。

### 4.2 初始数值假设

首个可玩版本使用以下基线：

- 初始本金：100；
- 正常档单次赌注：10；
- 保守档赌注倍率：0.5；
- 豪赌档赌注倍率：2.0；
- 退房目标：本金达到 200；
- 初始机器预计回报率：75%–85%；
- 默认每班干预点：2；
- 每次转动最多使用一次干预。

赌注倍率同时缩放成本和所有基础奖金，不直接改变机器回报率。部件如果根据赌注档位触发额外规则，必须在说明中明确显示。

默认正常档即便连续六次完全空转，玩家仍可进入第三班并看到至少两次构筑选择。主动选择豪赌档可以提前破产，这是明确的玩家风险。

### 4.3 胜利与续住

每个班次结束时检查本金。第一次达到 200 后，退房门解锁：

- 玩家可以立即带着金额退房并记录胜利；
- 玩家可以继续到第五班，争取更高金额和更完整构筑；
- 第五班结束仍未达到 200，则本局失败；
- 本金低于最低可选赌注且没有免费转动时，本局立即失败。

续住模式每三个转动把基础赌注提高 25%，基础奖金同比缩放，不额外收取会改变盈亏平衡阈值的强制费用。因此预计回报率超过 100% 的机器保持正期望，但有限本金和逐步增大的绝对波动仍可能导致破产。

## 5. 基础老虎机规则

### 5.1 转轮与中奖线

老虎机使用三列三行的可见网格，以及三个彼此独立的转轮条。每个转轮条由有序图案列表构成；一次抽取确定该轮显示的连续三格。

原型固定计算五条中奖线：

- 上、中、下三条横线；
- 左上至右下对角线；
- 左下至右上对角线。

玩家不单独购买中奖线。一次赌注始终激活全部五条线。

### 5.2 图案

原型包含六类基础图案：

1. 樱桃：常见、低奖金；
2. 柠檬：常见、适合感染和重复结算；
3. 铃铛：中等稀有、中等奖金；
4. 幸运 7：稀有、高奖金；
5. 百搭：可以替代普通图案完成中奖线；
6. 空白：默认无奖金，但可被故障构筑利用。

服务和构筑还会加入两类特殊图案：

- 食物：默认不参与中奖线。最终盘面出现食物时，将该图案从转轮条移除，并使之后三次转动的全部奖金增加 25%。多份食物分别计时，增益相加。
- 裂纹：默认不参与普通中奖线。最终盘面每出现一个裂纹，本转便按从右向左的顺序暂时禁用一个机器部件；结算结束后部件恢复。裂纹多于部件数量时，多余裂纹不产生禁用效果。

百搭只替代四种普通付费图案，不替代空白、食物或裂纹。特殊构筑可以为特殊图案定义自己的中奖线。

基础转轮条和奖金表必须通过自动模拟调至 75%–85% 初始回报率。具体图案副本数属于平衡配置，而不是硬编码在规则核心中。

### 5.3 真实概率原则

每个图案的基础概率由它在对应转轮条中的副本数量直接决定。构筑产生的添加、删除、替换和临时复制必须真实修改抽取空间。

游戏不使用未公开的动态难度、秘密保底或“差一点中奖”操控。所有补偿机制均作为公开状态进入规则，例如机器躁动、祈祷临时副本和裂纹图案。

## 6. 构筑系统

构筑同时改变三个层面：转轮条、机器部件和主要服务。

### 6.1 转轮条改造

转轮条升级可以：

- 增加指定图案副本；
- 删除空白或低价值图案；
- 把一种图案替换为另一种；
- 让左侧图案向右侧轮轴传播；
- 限制某图案只出现在特定轮轴；
- 加入食物、裂纹等特殊图案。

这些操作优先使用具体对象描述，例如“在第二轮加入两个柠檬”，而不是抽象描述“柠檬概率增加 10%”。

### 6.2 机器部件

玩家拥有五个机器部件槽。部件主要改变中奖后的规则和触发链。

示例能力包括：

- 柠檬中奖后把相邻图案变成柠檬；
- 既有樱桃中奖线提高之后的樱桃奖金；
- 幸运 7 中奖线额外结算并向转轮加入空白；
- 空白图案累计到阈值后奖励免费转动；
- 裂纹中奖后被拆除并支付故障奖金；
- 较长的效果链提高本转总奖金并制造新裂纹。

相同部件再次获得时升级原部件至二级，不占用第二个槽；二级部件不再进入候选池。槽位已满时，玩家必须替换一个部件或放弃新部件并换取一枚小费。各部件的二级效果在内容表后统一定义。

### 6.3 主要服务

一局只能装备一个主要服务。功能原型包含四种：

#### 维修服务

每班干预点上限和补充量从 2 增至 3。每班一次，玩家可以消耗一点干预点锁住一个轮轴并重转另外两个轮轴。班次结束时可以花费一枚小费，从选择的转轮条移除最多两个裂纹。定位是稳定、低波动。

#### 午夜厨房

每班开始时可以支付 10 本金，在选择的转轮加入一个食物；每班最多一次。食物遵循第 5.2 节的消耗与增益规则。定位是主动消费和复利。

#### 小教堂

每班一次，转动前消耗一点干预点并指定一种普通付费图案，为下一转的三个轮轴各加入两个临时副本；转动结束后移除临时副本。若最终盘面没有形成包含指定图案的中奖线，则祈祷失败并获得一层恶兆。定位是高风险大奖。

#### 保安服务

每班允许免费踹机器一次。踹机器让指定轮轴精确前进一个位置，同时在该轮加入一个裂纹。定位是确定性救场与可利用故障。

会计室不是第五个主要服务，而是提供一条独立的信息工具升级线，避免玩家为了看懂概率而放弃主动玩法。

### 6.4 信息工具

玩家拥有一个独立工具位，按以下顺序升级：

1. 无工具：只显示“凶险、接近持平、有利”等诚实的区间判断；
2. 计算器：显示各图案在每个轮轴的精确基础概率；
3. 会计账本：显示预计回报率范围；
4. 统计终端：增加波动率、预计续航次数和当前本金下的破产概率。

信息工具占用构筑候选机会，但不占五个机器部件槽。祈祷和诅咒可以暂时遮蔽高级数据；遮蔽状态必须预先写明。

### 6.5 候选生成

每次构筑三选一固定包含：

1. 一个与当前标签和转轮状态直接协同的选项；
2. 一个降低当前主要风险或允许转型的选项；
3. 一个高风险、能够改变规则的选项。

候选生成器不得完全依赖均匀随机抽取。它根据构筑标签生成候选，同时使用带种子的随机数保证可复现。

候选必须满足使用前提：没有午夜厨房时不提供依赖食物的“剩菜打包”，没有小教堂时不提供依赖祈祷或恶兆的部件，没有保安服务或其他裂纹来源时不提供只依赖裂纹的部件。候选生成器不能用当前局无法触发的选项填充三选一。

正式局外成长以酒店部门包横向解锁。开局启用有限部门包，避免内容越多、关键组件越难获得。该选择系统不在功能原型中实现；原型使用固定内容池验证三条构筑。

## 7. 首批构筑路线与内容量

功能原型包含二十四个构筑选项：三条路线各六个、三个通用选项、三个信息工具。四种开局主要服务和三种合同模板不计入这二十四个选项。

构筑选项分成三类：

- “转轮改造”选择后立即生效，不占部件槽；
- “机器部件”占用五个部件槽；
- “信息工具”升级唯一的工具位。

这些选项支持以下三条完整路线和少量混合：

### 7.1 水果自助餐

大量普通水果、低额连中、食物消耗和重复结算。目标是低波动、较早跨过 100% 回报率。

### 7.2 午夜弥撒

删除普通图案，集中幸运 7 和百搭，使用献祭、祈祷与恶兆放大倍率。目标是高波动和高上限。

### 7.3 暴力维修

利用空白、裂纹和故障，通过踹机器移动图案，并从部件失效或机器过载中获利。目标是用确定性干预驾驭负面状态。

### 7.4 二十四个原型选项

所有倍率均以本次转动的基础赌注为单位。一次“重新检查中奖线”只检查新产生的结果，不会再次触发已经在本转触发过且标注“每转一次”的部件。

#### 水果自助餐六项

| 名称 | 类型 | 原型效果 |
|---|---|---|
| 柠檬木箱 | 转轮改造 | 选择两个轮轴，各加入两个柠檬。 |
| 樱桃去核器 | 转轮改造 | 选择一个轮轴，移除其中一个非樱桃、非百搭图案，再加入一个樱桃。 |
| 柠檬感染 | 机器部件 | 每转第一次柠檬中奖后，把该中奖线右侧相邻的一个普通图案变成柠檬，并重新检查中奖线。 |
| 果酱罐 | 机器部件 | 本班每出现一条樱桃中奖线，之后的樱桃中奖线额外获得 0.5 倍赌注；班次结束清零。 |
| 水果沙拉 | 机器部件 | 同一中奖线同时包含樱桃、柠檬和铃铛时，按 1.5 倍赌注结算。 |
| 剩菜打包 | 机器部件 | 每班第一个被消耗的食物图案，在结算后加入当前图案数量最少的轮轴。 |

| 恶兆收集器 | 机器部件 | 祈祷失败额外获得一层恶兆；幸运 7 中奖时消耗全部恶兆，每层增加 0.5 倍赌注。 |

| 废料磁铁 | 机器部件 | 三个裂纹组成中奖线时支付 2 倍赌注，并从对应转轮条移除这三个裂纹。 |

| 殉道者硬币 | 支付相同代价后，本班幸运 7 奖金变为三倍。 |
| 废料磁铁 | 裂纹中奖线支付 4 倍赌注。 |
| 松动弹簧 | 踹机器前进三个位置，仍加入两个裂纹。 |
| 空白电容 | 累计显示两个空白后获得免费转动。 |
| 骗保单 | 首次触发支付 6 倍赌注。 |
| 过载马达 | 第二个效果事件起，每个后续效果增加 0.5 倍赌注。 |
| 安全保险丝 | 自动销毁时获得 40 本金。 |

转轮改造可以重复进入候选池并再次执行；信息工具只能按顺序升级。机器部件最多二级。

VIP 复利路线作为玩法验证后的第四条扩展路线，不进入首个原型内容范围。

## 8. 合同与小费

合同不替代退房金额，只提供班次内的额外目标。原型包含三种合同模板：

1. 组合合同：本班命中指定图案或中奖线次数；
2. 自律合同：本班不使用干预且结束本金不低于班次开始值；
3. 救场合同：使用一次干预把未中奖结果变成中奖结果。

每班随机提供一个符合当前构筑状态、且理论上可以完成的合同。完成后获得一枚小费。

小费仅用于以下两类动作：

- 刷新整组三个构筑候选，费用一枚；
- 支付主要服务明确标注的小费能力。

小费不能直接兑换本金，避免形成第二套通关货币。

## 9. 转动与人工干预

### 9.1 单次转动流程

1. 玩家使用可选的转前服务动作；
2. 玩家向下拖动并松手，或点击无障碍转动按钮；
3. 三个轮轴依次停下，基础停轮过程约两秒；
4. 状态进入干预窗口；
5. 玩家接受结果，或每转最多使用一次干预；
6. 规则核心依次结算中奖线和部件触发；
7. 界面播放结构化事件并进入下一转。

默认干预消耗一点干预点，重转玩家指定的一个轮轴。主要服务可以替换或增强该动作。

### 9.2 踹机器

踹机器不是随机重掷。它把指定轮轴向前推进一个确定位置，并加入一个裂纹图案。玩家在操作前可以预览将要推进到的可见结果，但无法预览裂纹未来造成的随机抽取。

### 9.3 机器躁动

完全没有基础奖金、部件充能或合同推进的转动会增加一格公开的机器躁动，最多五格。下一次产生奖金时，每格躁动额外支付 0.5 倍本次赌注，随后全部清空。

躁动不是秘密保底。玩家可以看到当前层数、下一次奖励和哪些部件会消费它。

## 10. 反馈与可解释性

### 10.1 因果结算

一次结算以事件链显示原因：

```text
三个柠檬
→ 柠檬感染
→ 新增中奖线
→ 餐后返现
→ 免费转动
```

中奖反馈分为三个强度层：普通中奖、构筑连锁和机器失控。触发链增强音效、颜色和震动，但不得改变真实结果。

长连锁首次完整播放；玩家可以长按加速或点击直接跳到总额。跳过表现不跳过规则结算。

### 10.2 收益归因

每次结算和班次总结分别显示：

- 基础中奖金额；
- 机器部件额外金额；
- 玩家干预挽回金额；
- 服务和合同带来的间接收益。

### 10.3 失败复盘

失败页面显示：

- 本局预计回报率的变化轨迹；
- 最大收入来源；
- 最大资金漏洞；
- 最接近成型但未完成的组合；
- 一条由规则生成的具体解释。

示例：“你的预计回报率已达到 108%–114%，但豪赌档使当前本金只能承受约两次空转。”

## 11. 移动端界面

功能原型采用已确认的“A：老虎机舞台”布局：

- 顶部显示本金、退房目标和班次；
- 其下显示当前信息工具允许查看的机器状态；
- 3×3 大老虎机占据屏幕中心；
- 当前干预和主要服务各使用一个上下文按钮；
- 五个机器部件压缩成一排可点击图标；
- 大拉动区域固定在底部拇指区。

首个原型以 390×844 CSS 像素为参考尺寸，同时支持 320×568 至 430×932 的常见竖屏范围。主要触控目标最小尺寸为 44×44 CSS 像素。

功能原型只验证信息层级和操作，不承诺最终视觉风格。震动属于增强反馈；设备或浏览器不支持震动时，不影响规则和可玩性。

## 12. 技术架构

### 12.1 技术选择

功能原型使用：

- TypeScript；
- Vite；
- React；
- CSS/Web Animations；
- PWA 安装能力；
- Vitest 规则测试；
- Playwright 手机浏览器测试。

规则核心不依赖 React、DOM 或浏览器动画。玩法验证成功后，可以用 Capacitor 打包移动应用，或者保留规则核心并替换表现层。

### 12.2 模块边界

```text
src/core       纯规则、状态机、随机数、转轮、结算和合同
src/content    图案、部件、服务、奖金表和标签配置
src/sim        RTP、波动和破产风险模拟
src/app        React 界面、输入映射和页面流程
src/presentation 事件动画、声音、震动和加速控制
tests          单元、场景、模拟和浏览器测试
```

界面只能向规则核心发送玩家指令，不能直接修改本金、转轮结果或触发效果。

### 12.3 状态机

允许的顶层状态为：

- `READY_TO_SPIN`；
- `SPINNING`；
- `AWAITING_INTERVENTION`；
- `RESOLVING_EFFECTS`；
- `CHOOSING_UPGRADE`；
- `SHIFT_COMPLETE`；
- `RUN_WON`；
- `RUN_LOST`；
- `AFTER_HOURS`。

状态不匹配的指令返回明确拒绝结果，不修改游戏状态。例如结算中重复拉动不会再次扣钱。

### 12.4 单次转动的数据流

```text
玩家指令
→ 状态机校验
→ 带种子随机数生成转轮结果
→ 可选干预指令
→ 规则核心生成事件列表
→ 最终状态立即确定
→ 表现层按事件列表播放
→ 自动保存序列化状态
```

表现层跳过或中断动画后，直接恢复规则核心已经确定的最终状态。

### 12.5 随机性与模拟

每局保存初始种子。相同初始状态、种子和指令序列必须产生完全相同的结果。

基础图案概率可以精确显示。包含触发链的预计回报率由后台批量模拟估算，并显示区间而非伪精确值。模拟不得消费实际游戏使用的随机数序列。

## 13. 异常与边界处理

- 本金不足：阻止转动，允许选择更低赌注；低于最低赌注且无免费转动时结束本局。
- 重复输入：状态机只接受当前状态允许的第一条有效指令。
- 单次无限触发：每转最多展开 100 个效果事件。达到上限后不再递归触发新效果，改为支付固定的 25 倍当前赌注“机器过载”奖金，并结束本转。事件上限与过载奖金均在规则说明中公开。
- 模拟超时：隐藏高级预计数据并显示“会计仍在计算”，实际游戏继续运行。
- 页面进入后台：暂停表现；恢复时可以继续播放或立即应用最终状态。
- 页面刷新：从最后一条已提交指令后的序列化状态恢复。
- 动画或音频失败：规则状态不回滚，玩家仍能继续。
- 非有限数值：任何 `NaN`、无穷大或超过安全整数的金额在规则边界被拒绝，并生成可导出的诊断事件。

原型保存当前运行状态和事件记录到浏览器本地存储。正式版本的跨版本迁移不在本原型范围内。

## 14. 测试与验收

### 14.1 自动测试

1. 规则单元测试覆盖中奖线、奖金、转轮修改、百搭、免费转动、干预、合同和全部二十四个构筑选项。
2. 确定性测试验证相同种子和指令序列得到相同事件与最终状态。
3. 属性测试验证金额始终为有限数值、单次转动必然终止、无效指令不修改状态、奖金不会重复提交。
4. 平衡模拟每次至少运行一万条完整局，比较三条构筑的通关率、跨过 100% 的班次和破产原因。
5. 场景测试为三条构筑各保留至少两个固定种子，验证其关键连锁仍然成立。
6. Playwright 覆盖竖屏拉动、单轮重转、候选选择、后台恢复、动画跳过、失败和续住。

### 14.2 功能原型 Go/No-Go

原型只有同时满足以下条件才进入美术和内容扩展：

- 至少三种操作逻辑不同的构筑能够通关；
- 熟悉规则后的选择对胜率影响明显大于初始种子；
- 至少 70% 试玩者能够说出上一局主要赢因或输因；
- 首次失败后，至少 50% 试玩者主动立即再开一局；
- 合理构筑通常在第三或第四班跨过 100% 预计回报率；
- 简单转动至结算约 2–4 秒；
- 任意连锁均可加速，并且单次规则结算必然终止；
- 玩家描述更接近“我把机器构筑起来了”，而不是“系统让我走运”。

若三条构筑只在名称和数值上不同，或者失败主要无法归因，则判定 No-Go，先修改核心规则，不增加美术、剧情或更多道具。

## 15. CloverPit 提供的设计参照

CloverPit 证明了“老虎机作为可被玩家操纵和击穿的概率机器”具有清晰卖点，也证明低操作量可以通过规则连锁、音效和数字爆发产生强反馈。其官方页面将核心描述为用护符、奖励和概率操控形成滚雪球构筑，并明确与真钱赌博区分：

- [CloverPit Steam 页面](https://store.steampowered.com/app/3314790/_CLOVERPIT/)
- [Panik Arcade 官方 FAQ](https://www.panikarcade.games/cloverpit)

本设计重点规避三个已观察到的风险：

1. 让玩家拥有稀缺的停轮后干预，减少连续被动拉杆；
2. 使用标签导向的候选生成，避免解锁越多、协同组件越稀释；
3. 使用收益归因、概率工具和失败复盘，让玩家理解胜负原因。

关于候选池稀释、早期信息晦涩和长期深度的外部评价参照：

- [PC Gamer 的 CloverPit 评测](https://www.pcgamer.com/games/roguelike/cloverpit-review/)
